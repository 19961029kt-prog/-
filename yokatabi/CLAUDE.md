# Q-TRIP 九州よりみちダイス — プロジェクトガイド

副題：**KYUSHU ROUTES & ROOTS**　〜サイコロ片手に巡る、ローカル美食と秘湯の旅〜

実際の地図と線路で描いた九州の路線図をすごろく盤にした、旅の手帖のようなインタラクティブマップ。遊びながら各駅の寄り道ノート・名産品・宿に出会い、お取り寄せ・宿の手配をして、その**購入実績（注文完了画面のスクショ）**で駅の**トップオーナー**を目指し、共同株主の配当で貯めた**クラフト資金**で列車を改造したりアバターを着せ替えたりできる体験型メディア（MVP）。

旧名は「よか旅すごろく九州」。フォルダ名 `yokatabi/`、localStorage のキー `yokatabi.kyushu.v1`、名前空間 `window.YT`、保存データの項目名（`acquired` など）は、遊んでいる人の保存データを守るため旧名のまま残している（画面・検索・共有に出る名前だけを変えた）。

このディレクトリ（`yokatabi/`）は、リポジトリ直下の Vite + React アプリとは**完全に独立した静的サイト**。ビルド工程はなく、ファイルをそのまま配信する。

## 1. North Star（すべての判断基準）

ユーザーが九州を **「気になる ➔ 購入する（お取り寄せ） ➔ 訪れる（旅行） ➔ 関係性がつづく」** の4段階でたどること。

| 段階 | プロダクト上の行動 | 記録先（localStorage） |
|---|---|---|
| 気になる | 駅に到着して寄り道手帖を読む | `visited` |
| 購入する | 名産品物件のボタン（Amazon／楽天市場／Yahoo!ショッピング）を押す | `actions[id].product` |
| 訪れる | 宿泊・体験物件のボタン（楽天トラベル／じゃらん）を押す | `actions[id].stay` |
| つづく | 推し駅に登録する | `favorites` |

寄り道手帖の上部の「ジャーニー」表示は、この4段階の達成状況をそのまま映す。駅のオーナー権は、ボタンから手配したあと、注文完了画面のスクショで立候補した購入実績（`purchases`）のランキングで決まる（3章）。新機能を足すときは、どの段階を前に進める機能なのかを説明できること。

## 2. 絶対ルール（法務・権利）

- **既存ゲーム（『桃太郎電鉄』等）の固有名称・画像・キャラクター・セリフ回し・ゲーム用語は一切使わない。** 世界観・UI・用語はすべてオリジナル。
- アプリ名：**Q-TRIP 九州よりみちダイス**、副題 **KYUSHU ROUTES & ROOTS**。英字はこの2つだけ（それ以外の見出し・ボタンは和文）。Xのハッシュタグは `#九州よりみちダイス` `#QTRIP`（ハッシュタグにハイフンは使えない）。
- 使ってよい独自用語：**よりみちダイス／寄り道手帖／車窓とまちの寄り道ノート／名産品物件／湯けむり物件／宿泊・体験物件／視察・手配中／トップオーナー／オーナー権ランキング／購入実績／立候補（オーナー権に立候補する）／下克上ボーナス／共同株主・配当／王座交代／ライバル旅人／AIスマート読取／査収スタンプ（Q-TRIP 旅の領収書）／レシートアルバム／旧版の記念刻印／オーナー刻印手帖／総資産額／クラフト資金／よりみち発見ボーナス／よりみち切符／鉄道クラフト工房／旅人アバター／九州踏破率／オーナー率／特別航路／分かれ道／経由駅／マイ旅しおり**、称号の **九州旅人／九州開拓使／九州大名／九州鉄道王**。
- 使わない語（既存作品を想起させる語）：社長、独占（「トップオーナー」と言う）、決算、目的地（ゲームの仕組みとしての）、カード名・キャラ名・イベント名の流用全般。迷ったら新しい言葉を作る。
- **実在の列車・会社**：鉄道会社のロゴ・車両の画像・公式路線図・実在の列車の名前・紋章は使わない。クラフト工房の車両は、九州の観光列車の**色づかいの雰囲気だけ**を借りたオリジナルの名前と絵（`js/craft.js`）。紋章も独自の図柄（楠の葉の丸紋）にする。コード・コメント・画面に実在の列車名を書かない。
- 実在の人物・動物の名前も使わない（旅の相棒の猫は「三毛猫の見習い駅長」。実在の駅長猫の名前は付けない）。
- **ステマ規制への対応**：アフィリエイトを含む箇所には必ず【PR】表記を置く（`meta.affiliate.disclosure`、フッター）。リンクには `rel="sponsored noopener"` を付ける。
- 実在しない「駅」を扱う場合（黒川温泉＝バス停、高千穂＝旧駅、屋久島＝航路）は `note` に明記し、画面にも出す。

## 3. マネタイズと、購入実績ランキングのオーナー権（`js/ownership.js`・`js/owner.js`・`js/receipts.js`）

**インテント泥棒** ＝ ユーザーが商品名だけ覚えて、別タブで直接検索して離脱すること。これを防ぐため、ご褒美（オーナー権）を **寄り道手帖の中のボタンから手配して、その完了画面のスクショを出すこと** にだけ結びつける。

### 3-1. 手配中（`pendingOwner`）
- ボタン（物販・宿）を押した瞬間は何も付かない。`pendingOwner = { stationId, via, providerId, provider, item, clickedAt }` を保存し、寄り道手帖の該当部分を「視察・手配中」の待機パネルに切り替える。ジャーニーの「購入する／訪れる」はこの時点で記録する。
- `visibilitychange` と `focus` で戻りを検知し、`Date.now() - clickedAt` を測る。**15秒未満**（`meta.owner.minAwaySeconds`）なら「まだ寄り道の途中…」と案内するだけ。**15秒以上**なら立候補シートを自動でひらく。手配中は再読み込みしても残す。「手配をとりやめる」で消せる。
- 立候補ボタン（手帖のランキングの下）は、その駅のショップ・宿のボタンを押したことがある（`actions[id]`）か、その駅が手配中のときだけ押せる（`Owner.canApply`）。商品名で別に検索しただけでは立候補できない。

### 3-2. 立候補シート（`#owner-sheet`）
1. **画像を置く場所だけ**（ドラッグ＆ドロップかファイル選択。画像以外・20MB超は断る）。手入力の欄は、読み取りのあとの確認フォームにだけ出す。
2. **AIスマート読取**：最低1秒の走査アニメーション（「🔍 旅のレシート・スクショから購入実績を解析中…」）のあいだに、`Receipts.recognize`（Tesseract.js、日本語）で文字を読み、`Receipts.parse` が金額とショップを取り出す。
   - 金額：「合計」「お支払い金額」「ご請求額」など（重み3）＞「小計」「料金」（重み1）の近くにある金額を優先。どれもなければ一番大きい額。50円〜`maxAmount`（100万円）の範囲だけ。ほかに見つかった額は候補ボタンで選べる。
   - 文字認識のくせを先にそろえる（`normalizeText`）：日本語の文字間の空白、全角数字、`\`→`¥`（日本語の文字コードでは同じ場所）、桁の `.`→`,`（`4.800`・`30.,000`）。
   - ショップ：`meta.owner.shops` の `match`（正規表現）で判定。楽天トラベルは楽天市場より先に並べる。
   - 読み込めない・読めないときは、確認フォームに手で金額を入れられる（立候補はできる）。
3. **同じスクショは二度使えない**：元の画像のバイト列の指紋（FNV-1a を2通り、`Receipts.fingerprint`）を `purchases[].hash` に持ち、一致したら断る。
4. **見込みの表示**（`Ownership.preview`）：ランキングに入る額（下克上ボーナス込み）・累計・何位になるか・1位まであといくら（必要なお買い物の額＝差額÷1.3 の切り上げ）。
5. **「オーナー権を確定する」**：朱の「【査収】Q-TRIP 旅の領収書（日付）」スタンプがバン！と押される演出（`receipt-slam`）→ サムネイルを IndexedDB に保存 → `Ownership.register` → 1位を取ったら王座交代の演出（ファンファーレ・紙吹雪・称号のカットイン）、それ以外は順位と配当のトースト。

### 3-3. ランキングのしくみ（`YT.Ownership`）
- サーバーはないので、競う相手は `stations.json` の**ライバル旅人**（架空。`meta.rivals` の8人のうち、各駅の `rivals` に3人と金額）。自分の行は `purchases[id]` の `scored` の合計。表示名は `profile.name`（空なら「あなた」）。
- 並びは金額の大きい順。同じ額ならライバルが上（追い越さないと上がらない）。**1位＝トップオーナー**（地図の金の印・総資産額・称号・旅しおりの対象。`Ownership.sync()` が `acquired` に書き戻す）。
- **下克上ボーナス**：立候補する時点で1位でなければ、申告額 × `meta.owner.upsetBonus`（1.3）を数える（`scored`・`upset`）。
- **共同株主**：上位 `meta.owner.shareholders`（3）名は、駅の評価額（万円）を3名の中での金額の割合で分け合う（配当）。配当の合計はクラフト資金に入る。地図では駅に「株」の札が付く。
- ライバルの額は固定なので、一度1位になれば抜き返されない（推定の設計。抜き返しを入れるならここを変える）。

### 3-4. 守ること
- **スクショは端末の外に出さない**。注文画面には名前・住所・注文番号が写るため。保存は 480px に縮めた JPEG だけを IndexedDB（`qtrip-receipts` / `images`）に置き、localStorage には画像のIDと指紋だけを持つ。文字の読み取りも端末の中（Tesseract.js が CDN から取ってくるのはプログラムと辞書だけで、画像は送らない）。
- **ご褒美はゲームの中だけ**。順位・配当・クラフト資金にお金の価値はない。実際に購入したかは確かめられない（スクショは作れる）ので、シートにも「ご自分の購入だけを記録してください」と書く。
- **本番の前に**：Amazon アソシエイト・楽天アフィリエイト等の規約（購入の見返りを約束する・購入を促す特典の扱い）に照らして、この仕組みが問題ないか確認する。
- リンクは新しいタブで開くので、`preventDefault` しない（ポップアップブロック対策）。
- 旧版（version 1：ボタンと刻印シートだけでオーナーになれた頃）の刻印は、購入実績がないので順位に入れず、`legacyStamps` に移して「旧版の記念刻印」としてアルバムに残す。

- **技術スタック**：HTML5 / 自前の CSS / Vanilla JS / インラインSVG / CSS 3D / Web Audio API / IndexedDB。npm もビルドも不要（以前の Tailwind CDN はやめた）。
- **外部への依存はふたつだけ**：Google Fonts と、スクショの文字読み取りの **Tesseract.js 5.1.1**（jsDelivr。版は `receipts.js` の `TESS` で固定）。Tesseract.js は画像を置いたときにだけ読み込む（初回は約6MB、以後はブラウザのキャッシュ）。
- **スクリプトは classic script（`<script src>`）で読み込む。** ES Modules は `file://` で開くと CORS で止まるため使わない。モジュール間は `window.YT` 名前空間で受け渡す。読み込み順は `index.html` の末尾にある順のまま（craft → map → dice → trip → ownership → receipts → owner → garage → app）。
- **データ読み込み**：`fetch('stations.json')` を試し、`file://` や通信エラーのときは `window.YOKATABI_FALLBACK_DATA` を使う（`YT.Data.load()`）。フッターに「stations.json 読込済み／内蔵データで起動中」が出る。
- **効果音（`sound.js`）**：外部の音声ファイルは使わない。電子音のビープではなく、ノイズ＋フィルター＋倍音で、木のダイスが革のトレイで転がる「コロン」、レールの継ぎ目の「ガタン、ゴトン」（走った距離に合わせて鳴る）、駅メロ風のメジャーセブンスのアルペジオ（オルゴール／エレピ風・薄いディレイ）、刻印の「バン！」と弦のストロークのファンファーレ、工具の「カン」と和音の改造ファンファーレをつくる。AudioContext は最初のユーザー操作で作り、無音を一瞬鳴らして起こす。iPhone 対策として、`navigator.audioSession.type = 'playback'` と、別タブから戻ったときの 'interrupted' からの復帰を入れている。ミュートはヘッダーのボタンで、状態は保存する。
- **localStorage** のキーは `yokatabi.kyushu.v1`。読み書きはすべて try/catch で囲み、使えない環境ではメモリ上の状態で動かす。項目を足すときは `blank()` に初期値を書けば古いデータにも補われる。構造を壊す変更をするときは `version` を上げて、`store.js` の `normalize()` に移行処理を書く（いまは version 2。旧URLからの引き継ぎも同じ `normalize()` を通る）。レシートの画像は IndexedDB の `qtrip-receipts`（使えない環境では開いているあいだだけメモリに持つ）。


## 5. データ構造（stations.json）

```jsonc
{
  "schemaVersion": 1,
  "meta": {
    "title": "Q-TRIP 九州よりみちダイス", "subtitle": "KYUSHU ROUTES & ROOTS", "catch": "…",
    "viewBox": [0, 0, 800, 960],       // SVG座標系。駅の x/y はこの中の値（latLngToSvg の出力）
```

### 盤面のデザイン（`map.js`・`style.css` の「すごろくマップ」）
- **重ね順**：海（ペールブルー `#D8ECEB`〜`#BFE0DF` のグラデーション＋水彩のにじみ＋波の模様）→ 経緯線（0.5度ごと、1度ごとに度数）・コンパス・船の線画 → 対岸（山口・愛媛）→ 浅瀬 → 陸地（サンドベージュ `#F4EBD9`）→ 県のうす色・山地（セージ `#D5E2C8` ほか3段）・紙の質感 → 海岸線・県境（`#B8A68E` の破線 4,4）→ 実在の JR 線路網（細線）→ 山の名前・海の名前 → すごろくの路線 → 区間のしるし・経由駅 → **県名** → モデルコース → 駅 → 列車。
- **県名**（`PREF_LABELS`）：しっぽり明朝 700、`fill: #6E5D4F`、`letter-spacing: .25em`、白フチ `paint-order: stroke fill; stroke: rgba(250,246,240,.9); stroke-width: 5px`。線路や駅とぶつからない各県の空き地（国東半島・西彼杵半島・薩摩半島の内陸など）に、**緯度・経度**で置く。
- **駅**：生成りの丸いスタンプ台に県の色のふち。訪問済みは中が県の色、トップオーナーの駅は山吹の封蝋に「印」、共同株主（2〜3位）の駅には「株」の札。今いる駅と行き先候補は波紋。スマホでは駅名・県名の字を大きくし、経由駅の名前と経緯線の度数を省く。
- **路線**（`ROUTE_STYLES`）：

| type | 見た目 | 割り当ての考え方 |
|---|---|---|
| `shinkansen` | 枕木の上に深緑の二重線（中が生成り）、生成りの帯がゆっくり流れる | 九州新幹線・西九州新幹線の区間 |
| `trunk` | ダークブラウンの線路（細かい枕木つき） | 特急が走る幹線（鹿児島本線・日豊本線・長崎本線など） |
| `local` | 深緑の細い線路 | ローカル線（JR・第三セクター） |
| `scenic` | テラコッタの線路に山吹の飾り線＋✦ | 観光列車が走る路線（列車の商品名は書かず、路線名で示す） |
| `ferry` | 白い航跡の上を浅葱の点線が流れる＋⛴ | 離島への航路 |
| `bus` | テラコッタの丸い点線＋🚌 | 鉄道がない区間のバス連絡（実際に鉄道がない区間を鉄道として描かない） |

- **列車**：絵文字ではなく、クラフト工房で選んだ車両の SVG（`YT.Craft.trainSvg` / `carriageSvg`）。経路の各区間の `<path>` を `getPointAtLength()` でなぞり、線路の向きに回して置く（左へ向かうときは絵を裏返して上下さかさまにしない）。2両目を連結していれば、1両目の約54単位うしろ（道のりの距離を遅らせた位置）を走る。1駅ずつ経由し、出発・到着で加減速、途中の駅の前ではゆるめ、走りながら小さく揺れる。煙突から選んだトレイル（綿雲・木の葉・湯けむり・星くず）がふわっと浮かぶ（停車中もときどき）。駅の少し手前で止まり、駅のしるしを隠さない。
- **スマホ**（幅639px以下）では、座標系は 800×960 のまま、表示する範囲（viewBox）だけ左右の海を少し切って九州を大きく見せる（`Map.fit()`）。

### 地図データ（`js/geo.js`）：実在の地理データから作る
海岸線・県境・山地・線路・駅を、実際の地図に合わせる。手描きの近似はしない。

- **作り方**：`bash tools/fetch-geo-data.sh <データのフォルダ>` で元データを取り、`node tools/build-geo.mjs <データのフォルダ>` で `js/geo.js` と各駅の `x`/`y`（stations.json）を作る。続けて `node tools/build-fallback.mjs`。元データは大きい（約100MB）のでリポジトリに入れない。
- **投影 `latLngToSvg(lat, lng)`**：北緯 30.15〜34.05°・東経 129.35〜132.05° が viewBox 800×960 に収まるよう、正距円筒図法（範囲の中央の緯度 32.1° で経度を cos 倍に縮める）で**縦横同じ倍率**に変換する。範囲の縦横比が盤面と違うので、縦をちょうどに合わせ、左右の余りは海として見せる（縦横を別の倍率で引き伸ばすと九州が横に太るため）。盤面1単位 ≒ 0.45km。`geo.js` の `proj` に定数を書き出し、`map.js` の `latLngToSvg` も同じ式を使う。屋久島・種子島もずらさず実際の位置に描く。
- **盤面に入る島だけ**：重心が盤面の外にある島（対馬・五島の西側など）は描かない。
- **海岸線・県境**：国土数値情報「行政区域（N03）」。県の輪を線分に分け、同じ県で2回出てくる線分（市町村の境）を消して県の外周を出し、2県に共通する線分を県境、残りを海岸線にする。Douglas-Peucker で間引く（海岸線 0.3 単位）。
- **山地**：標高タイル Terrain Tiles（Terrarium 形式・ズーム9、約260m格子）を並べ、少し均してから、400m・800m・1200m 以上のマスの外周をたどって等高線の輪にし（N03 と同じ「境の辺だけを残す」考え方）、Chaikin でなめらかにして間引く。阿蘇のカルデラは中が低いので、輪の内側が抜けて外輪山の形が出る。
- **線路**：下地の線路網は JR九州の路線だけ（`n02/` に国土数値情報「鉄道（N02）」の RailroadSection を置けばそれから、無ければ station_database の線形＝N02 を加工したもの）。すごろくの区間は `LEGS` に「路線コード・発駅・着駅」を並べ、実際の線路の上を最短でたどる（鳥栖・久留米・日田・立野・行橋・中津・延岡・都城・川内・諫早・早岐などを実際に通る）。バス・航路は通過点を経度緯度で書いて曲線にする（経路のイメージ）。
- **経由駅**（`WAYPOINTS`）：すごろくのマスではないが、路線の通り道の目印として小さく描く駅。位置は station_database の緯度経度。
- **駅**：`PLACES` に、鉄道駅は station_database の駅（緯度経度は駅データ.jp 由来）、旅のマス（黒川温泉・高千穂・屋久島）は代表地点の経度緯度を書く。
- **検証**：ビルドのたびに、鉄道の各駅と経由駅について「JR 線路網からの距離」「その駅から出る区間の線路からの距離」を測り、1単位（約450m）を超えたら失敗させる（いまは最大0.16単位）。
- **出典**：`geo.js` の `source` に書き、フッターに自動で出す。いまは「国土数値情報『行政区域（N03）』（国土交通省）を加工」「Terrain Tiles（Mapzen・AWS Open Data。SRTM・GMTED2010 は U.S. Geological Survey、ETOPO1 は NOAA 提供）の標高を加工」「station_database（CC BY 4.0。線形は国土数値情報『鉄道（N02）』を加工、駅の位置は駅データ.jp 由来）」。
- **配布元について**：国土交通省の配布元（nlftp.mlit.go.jp）にこの開発環境からは接続できなかったため、N03 は niiyz/JapanCityGeoJson の GeoJSON を使い、N02 は station_database の線形を使っている。配布元から取った N03 の GeoJSON（`n03/`）・N02 の RailroadSection（`n02/`）を置けば、そのまま読める（N02 は属性 N02_002・N02_004 を見る）。
- **重さ**：`geo.js` は約330KB（山地が約100KB）。点を増やすときは `simplify` の許容値で調整する。

### アフィリエイトURLの組み立て（`app.js` の `buildUrl`）

### 駅を追加するとき（100駅以上への拡張）
1. `stations.json` の `stations` に1件足す（`x`/`y` は仮の値でよい）
2. 接続する駅の `connections` にも **お互いに** IDを書く
3. 新しい区間の `routeOverrides` に `type`・`name`・`minutes` を足す。離島は `type: "ferry"`
4. `tools/build-geo.mjs` の `PLACES`（駅の位置）と `LEGS`（区間がたどる路線）に足し、`node tools/build-geo.mjs <データのフォルダ>` で `x`/`y` と線形を作る（駅が線路から離れていれば失敗する）
5. `node tools/build-fallback.mjs` を実行する
6. 画面で、駅名・県名・経由駅の名前がぶつかっていないか確かめ、必要なら `labelDir`・`PREF_LABELS`・`WAYPOINT_QUIET` を直す

## 6. マイ旅しおり（トップオーナーの駅を巡る1泊2日のモデルコース）

North Star の「購入する → **訪れる**」をつなぐ機能。オーナー刻印手帖の中の「🧳 マイ旅しおり」でひらく（右側のミニ手帖のボタン・刻印の完了演出のボタンからも）。トップオーナーの駅が `meta.trip.minAcquired`（2駅）に届いた瞬間に一度だけ提案する（`tripPrompted`）。

- **生成（`YT.Trip.generate`）**：区間の `minutes` で全駅間の最短経路を出し、路線が変わるごとに `transferMinutes` を足す。1日目は gateway を `day1Start` に出発 → オーナーの駅を巡る → そのどこかに泊まる。2日目は泊まった駅で朝の過ごし方 → 巡る → gateway に `day2End` までに着く。時間内に収まる道順をすべて探して採点する（巡れる駅の数 ≫ 湯けむり物件に泊まる ＞ 評価額の合計 ＞ 移動の短さ）。候補は最大3プラン。入りきらない駅は正直に表示し、2日目が早く終わるときはまだオーナーでない近くの駅を「寄り道候補」に出す。
- **宿の比較**：このプランの宿泊地と、ほかの候補プランの宿泊地を並べ、楽天トラベル・じゃらんのボタンを置く。押すと、その駅の「視察・手配中」になる（オーナー権は3章の流れで）。出発日はしおりの表示用で、予約サイトのURLには渡さない。
- **保存**：localStorage の `itineraries` に道順（`seq`）だけを保存し、開くたびに最新データで旅程を組み立て直す。「旅の記録をリセット」では消さない。
- 生成ロジックを変えたら `node tools/test-trip.mjs` を通す。

## 7. 称号（トップオーナーの駅の資産の合計でランクアップ）

`meta.ranks` の順に **九州旅人（0円〜）➔ 九州開拓使（1億円〜）➔ 九州大名（3億円〜）➔ 九州鉄道王（5億5,000万円〜）**。総資産額（トップオーナーの駅の評価額の合計）で決まる。ライバルの額は固定なので、いまの仕組みでは減らない。

- ヘッダーの称号バッジ（押すとオーナー刻印手帖へ）と、手帖の「称号の道」。王座交代のたびに `checkRankUp` が比べ、上がっていたら演出のあと（約2.6秒後）に、縫い目のある紙の帯のカットインを重ねる。7秒で自動的に閉じ、クリック・Esc でも閉じる。出し終えた段階は `rankSeen` に保存する。
- しきい値や名前を変えるときは `meta.ranks` を編集する（`build-fallback.mjs` が検証）。

## 8. ゲームロジック

- **よりみちダイス**：出目 n に対し、**同じ駅を二度通らない n 区間の道のり** の終点を行き先候補にする（行き止まりなら届く最長距離）。候補は **ランダムに最大3駅**（分かれ道）。候補が1駅で、よりみち切符も残っていなければ自動で出発する。
- **よりみち切符**：その日に残っている枚数だけ、ダイスのあとに出目を −1／＋1 できる（1未満にはしない）。使うと候補を出し直す。
- **駅を直接タップ**：最短経路（BFS）で移動する。
- **指標**：九州踏破率＝訪問駅数／全駅、オーナー率＝トップオーナーの駅数／全駅、総資産額＝トップオーナーの駅の `assetValue` の合計（全15駅で6億7,500万円）、クラフト資金＝下の式。

## 9. クラフト経済（`js/craft.js`・`js/garage.js`）

- **クラフト資金**＝ 発見ボーナス（`meta.craft.discoveryBonus` 200万円）× 初到着した駅の数 ＋ 共同株主の配当の合計（`Ownership.totalDividends()`）− 使った額（`spent`）。0未満にはしない。残高は保存せず毎回計算する。総資産額は使っても減らない。
- **パーツ**（`meta.craft.train` / `avatar`）：車体フォルム＆塗装（6種）、2両目・連結車両（3種）、走行トレイル（4種）、帽子・頭（4種）、衣装（4種）、旅の相棒（3種）。各欄に0円の初期装備が1つ（`store.js` の `equipped` の初期値と同じID。`build-fallback.mjs` が検証）。アンロックするとすぐ装備する。
- **よりみち切符**：`ticket: true` のパーツ（高級車両・連結車両）を1つアンロックするごとに1日1枚増え、最大 `ticketMax`（3）枚。
- **絵**：列車（横から見た姿・1両は長さ120）とアバター（胸から上・viewBox 120×140、ヘッダー用は顔まわりを切り出し）は `craft.js` の SVG。マップの列車・ガレージのプレビュー・ヘッダーのアイコン・手帖のオーナー証・切手のカードで同じ絵を使う。
- **プレビューステージ**：九州の風景（山並み・噴煙の火山・海・高原・小さな駅）の前を、改造した列車（1両目＋2両目）がトレイルを浮かべながら走り、アバターがホームで待つ。パーツを替えるとすぐ絵が替わり、改造ファンファーレ（アンロック）・「カチッ」（付け替え）が鳴る。
- 配当は「駅の評価額 × 上位3名の中での自分の割合」なので、全15駅で1位でも評価額の全額にはならない（大きく引き離すほど増える）。全パーツの合計は約8億1,500万円なので、全部はそろわない（どれを選ぶかを楽しむ設計）。

## 12. デプロイ

- **公開URL：`https://q-trip.github.io/`**（GitHub の組織 `q-trip` のリポジトリ `q-trip/q-trip.github.io`。既定のブランチ `main` に置いたファイルがそのまま公開される）。

## 13. コーディング規約

- 依存ライブラリを増やさない（Google Fonts と、必要になったときだけ読む Tesseract.js のみ）。地図の元データはビルド時にだけ使い、ページは `js/geo.js` だけを読む。
- 文字列を HTML に差し込むときは必ず `esc()` を通す（データは自前でも、将来の外部データ化に備える）。
- 画面の文言は日本語（英字はアプリ名と副題だけ）。コメントも日本語で、ねらい（なぜそうするか）を書く。
- アニメーションは `prefers-reduced-motion` で弱める（`style.css` の末尾。ダイスは短く、列車は速く、トレイルは出さない）。
- キーボードで操作できること：駅ノードは Tab で選べて Enter で動く。モーダル・立候補シート・演出は Esc で閉じる。画像を置く場所はファイル選択のボタンとしても使える。
