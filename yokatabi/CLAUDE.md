# Q-TRIP 九州よりみちダイス — プロジェクトガイド

〜サイコロ片手に巡る、ローカル美食と秘湯の旅〜

九州の路線図をすごろく盤にしたインタラクティブマップ。遊びながら各駅のローカル1次情報・特産品・宿を発見できる体験型メディア（MVP）。

旧名は「よか旅すごろく九州」。フォルダ名 `yokatabi/`、localStorage のキー `yokatabi.kyushu.v1`、名前空間 `window.YT` などの内部の名前は、遊んでいる人の保存データを守るため旧名のまま残している（画面・検索・共有に出る名前だけを変えた）。

このディレクトリ（`yokatabi/`）は、リポジトリ直下の Vite + React アプリとは**完全に独立した静的サイト**。ビルド工程はなく、ファイルをそのまま GitHub Pages で配信する。

---

## 1. North Star（すべての判断基準）

ユーザーが九州を **「気になる ➔ 購入する（お取り寄せ） ➔ 訪れる（旅行） ➔ 関係性がつづく」** の4段階でたどること。

| 段階 | プロダクト上の行動 | 記録先（localStorage） |
|---|---|---|
| 気になる | 駅に到着して物件カードを読む | `visited` |
| 購入する | 名産品物件のボタン（Amazon／楽天市場／Yahoo!ショッピング）を押す | `actions[id].product` |
| 訪れる | 宿泊・体験物件のボタン（楽天トラベル／じゃらん）を押す | `actions[id].stay` |
| つづく | 推し駅に登録する | `favorites` |

物件カード上部の「ジャーニー」表示は、この4段階の達成状況をそのまま映す。新機能を足すときは、どの段階を前に進める機能なのかを説明できること。

## 2. 絶対ルール（法務・権利）

- **既存ゲーム（『桃太郎電鉄』等）の固有名称・画像・キャラクター・セリフ回し・ゲーム用語は一切使わない。** 世界観・UI・用語はすべてオリジナル。
- アプリ名：**Q-TRIP 九州よりみちダイス**（「Q-TRIP」の札＋「九州よりみちダイス」）。Xのハッシュタグは `#九州よりみちダイス` `#QTRIP`（ハッシュタグにハイフンは使えない）。
- 使ってよい独自用語：**名産品物件／湯けむり物件／宿泊・体験物件／買収完了／正式オーナー／王国経営度／総資産額／九州踏破率／現地調査メモ／コレクション手帳／特別航路／分かれ道／マイ旅しおり**、称号の **九州旅人／九州開拓使／九州大名／九州鉄道王**。
- 使わない語（既存作品を想起させる語）：社長、独占、決算、目的地（ゲームの仕組みとしての）、カード名・キャラ名・イベント名の流用全般。迷ったら新しい言葉を作る。
- 鉄道会社のロゴ・車両の画像・公式路線図は使わない。列車は絵文字（🚂）、地図は自作SVG。
- **ステマ規制への対応**：アフィリエイトを含む箇所には必ず【PR】表記を置く（`meta.affiliate.disclosure`、フッター）。リンクには `rel="sponsored noopener"` を付ける。
- 実在しない「駅」を扱う場合（黒川温泉＝バス停、高千穂＝旧駅、屋久島＝航路）は `note` に明記し、画面にも出す。

## 3. マネタイズとインテント泥棒対策

**インテント泥棒** ＝ ユーザーが商品名だけ覚えて、別タブで直接検索して離脱すること。これを防ぐため、ゲーム上のご褒美を **モーダル内のアフィリエイトボタンを押すこと** にだけ結びつける。

- 物件カード内のボタンを押す → 新しいタブで販売・予約サイトが開く ＋ その駅が **買収完了**（初回のみ）。
- 買収完了で起きること：
  1. マップの駅ノードが **山吹の金メダル** になる（縫い目のような点線の輪・広がる波紋・王冠）
  2. マップ右側のミニ手帳と、コレクション手帳タブに **旅のスタンプカード**（評価額・買収日・買収ルート・朱のはんこつき）が加わる（新しいカードは裏返しから登場）。コード上のクラス名は以前の「ホログラムカード」の名残で `.holo` のまま
  3. ヘッダーの **王国経営度（買収率％）＆ 総資産額（万円）** がカウントアップする
  4. Xシェア文面が「〇〇駅に到着！」から **「【〇〇駅】を評価額〇〇万円で完全買収しました！✨」** に変わる
- 実際に購入したかどうかは検証しない（MVPは「ボタン経由で行動した」ことを買収とする）。本番でコンバージョンを検証する場合も、ゲーム体験側は「ボタンを押したら即買収」のまま保つ。
- リンクは新しいタブで開くので、`preventDefault` しない（ポップアップブロック対策）。買収の演出は元のタブ側で再生され、戻ってきたときに見える。

- **技術スタック**：HTML5 / Tailwind CSS（Play CDN、バージョン固定）/ Vanilla JS / インラインSVG。npm もビルドも不要。
- **スクリプトは classic script（`<script src>`）で読み込む。** ES Modules は `file://` で開くと CORS で止まるため使わない。モジュール間は `window.YT` 名前空間で受け渡す。読み込み順は `index.html` の末尾にある順のまま。
- **データ読み込み**：`fetch('stations.json')` を試し、`file://` や通信エラーのときは `window.YOKATABI_FALLBACK_DATA` を使う（`YT.Data.load()`）。フッターに「stations.json 読込済み／内蔵データで起動中」が出る。
- **効果音**：外部の音声ファイルは使わない。サイコロ（コトン・コロコロ）、出目の確定音、発車・到着チャイム、買収ファンファーレをすべて OscillatorNode とノイズバッファで合成する。AudioContext は最初のユーザー操作（どこをタップしても）で作り、無音を一瞬鳴らして起こす。iPhone 対策として、`navigator.audioSession.type = 'playback'`（消音スイッチがオンでも鳴る）と、別タブから戻ったときの 'interrupted' からの復帰を入れている。ミュート状態は保存する。
- **localStorage** のキーは `yokatabi.kyushu.v1`。読み書きはすべて try/catch で囲み、使えない環境ではメモリ上の状態で動かす。構造を変えるときは `version` を上げて移行処理を書く。

### デザインシステム「ほっこり旅の絵地図」（ほっとする、温かみのある見た目）
紙・木・布・はんこの手ざわり、丸み、やわらかい茶系の影。トークンは `css/style.css` 冒頭の `:root`（`--paper*`・`--ink*`・`--kaki*`・`--gold*`・`--cyan*`・`--shadow*`・`--washi`）にまとめてある。新しい色を直書きせず、まずトークンを使う。

- **使わないもの**：ネオン・光り物（発光・光の筋・後光・きらめき・虹色の箔）・ダーク基調・英字の見出し。見出しや演出の文言はすべて和文。
- **色の役割**：柿色＝押せる・進む、山吹＝買収・資産、浅葱＝海・新幹線・航路、県の色＝駅。
- **背景**：生成りの和紙（`--paper` ＋ 繊維のノイズ `--washi` ＋ ほのかな日だまり）。
- **盤面**：`.map-frame` は生成りの台紙を四隅のマスキングテープで留めた絵地図。`.map-board` は水彩の海。凡例は地図の下の帯（地図の上に重ねない）。
- **大地**：紙を切り抜いて貼ったような陸地に、県の色をほんのり重ね、県境は点線。浅瀬のにじみは細め（大村湾のような細い湾が埋まらない太さ）。
- **路線**：昔ながらの鉄道地図の記号をやわらかい色で（下の表）。
- **駅**：県の色のぷっくりしたシール（白いふち）。未訪問は淡く、訪問済みははっきり、買収済みは山吹の金メダル（縫い目の輪・波紋・王冠）。
- **列車**：生成りの丸いコマ。走ると湯気のような煙をぽわぽわ残し、跳ねて着地する。
- **パネル**：紙のカード。見出しは `.card-kicker`（例：さいころ／いまいる駅／旅の手帳）。サイコロは象牙色の木（1の目だけ赤）、メインボタンは柿色のぷっくりボタン。
- **スタンプカード**：和紙の台紙に県の色の水彩、ふちは縫い目のステッチ、真ん中に物件の印（♨／🎁）、右上に朱のはんこ（買収完了の大きなカードでは真ん中に大きく）。傾けると水彩のにじみがゆっくり動く。
- **称号**：フェルトのワッペン（縫い取りのふち）。旅人＝こげ茶、開拓使＝藍、大名＝山吹、鉄道王＝紅。
- **ロゴ**：柿色の荷札「Q-TRIP」＋「**九州**よりみちダイス」（九州だけ柿色）。英字はこのアプリ名だけの例外で、丸ゴシックの小さな札にして見出しの書体では書かない。幅 639px 以下では札を名前の上に載せる。
- 新しい要素を足すときも「紙・木・布・はんこ」のどれかで質感を持たせる。
- 幅 375px のスマホと PC の両方で崩れないこと（ヘッダーは1行、物件カードの下のボタンは1行、手帳のはんこは駅名にかぶらない）。

### 路線種別と盤面のデザイン（`map.js` の `ROUTE_STYLES`、`style.css` の「路線」）
| type | 見た目 | 割り当ての考え方 |
|---|---|---|
| `shinkansen` | 藍のふちどりに生成りの太い帯、藍の筋がゆっくり流れる | 九州新幹線・西九州新幹線の区間 |
| `trunk` | こげ茶と生成りの交互の帯（JR線の記号） | 特急が走る幹線（鹿児島本線・日豊本線・長崎本線など） |
| `local` | 細い交互の帯 | ローカル線（JR・第三セクター） |
| `scenic` | 枕木の上にえんじのレールと山吹の飾り線＋✨ | 観光特急・観光列車が走る路線（列車の商品名は書かず、路線名で示す） |
| `ferry` | 白い航跡の上を浅葱の点線が流れる＋⛴ | 離島への航路 |
| `bus` | 柿色の丸い点＋🚌 | 鉄道がない区間のバス連絡（実際に鉄道がない区間を鉄道として描かない） |

- 区間の真ん中のしるし（✨⛴🚌）は、長さ60未満の短い区間では駅名とぶつかるので省く。路線にマウスを乗せると `name` がツールチップで出る。
- 盤面は下から「海の波模様 → 浅瀬のにじみ → 対岸（山口・愛媛）→ 陸地（海岸線の太線＋塗り）→ 県の色・和紙の質感・山地・外輪山・県境・県名 → 実在の JR 線路網 → 山アイコン・地名」の順に重ねる。形はすべて `js/geo.js`（下の「地図データ」）から。
- 山地・山・県名・海の名前は `map.js` の `HIGHLANDS`・`PEAKS`・`PREF_LABELS`・`SEAS` に**経度・緯度**で書き、`project()` で盤面に置く。駅名とぶつからない位置に置き、駅を増やしたら必ず画面で重なりを確認する。

### 地図データ（`js/geo.js`）：実在の地理データから作る
海岸線・県境・線路・駅を、実際の地図に合わせる。手描きの近似はしない。

- **作り方**：`bash tools/fetch-geo-data.sh <データのフォルダ>` で元データを取り、`node tools/build-geo.mjs <データのフォルダ>` で `js/geo.js` と各駅の `x`/`y`（stations.json）を作る。続けて `node tools/build-fallback.mjs`。元データは大きい（約100MB）のでリポジトリに入れない。
- **投影**：正距円筒図法（中央緯度 32.5° で経度を cos 倍に縮める）。九州の広さなら見た目の歪みはほぼない。海岸線・県境・線路・駅を**すべて同じ式** `proj()` で盤面の座標にするので、駅が線路から浮かない。倍率は本土（平戸〜佐伯、佐多岬〜門司）が盤面に入るよう自動で決める（盤面1単位 ≒ 0.45km）。`geo.js` の `proj` に定数を書き出し、`map.js` の `project()` も同じ式を使う。
- **屋久島**：本土から約60km南で盤面に入らないので、縮尺はそのままで位置だけ左下へずらす（`yaku.shift`）。画面に「位置をずらして表示」と出す。
- **盤面に入る島だけ**：重心が盤面の外にある島（五島・対馬・種子島など）は描かない。壱岐・平戸・天草・甑島などは描く。
- **海岸線・県境**：国土数値情報「行政区域（N03）」。県の輪を線分に分け、同じ県で2回出てくる線分（市町村の境）を消して県の外周を出し、2県に共通する線分を県境、残りを海岸線にする。Douglas-Peucker で盤面に合わせて間引く（海岸線 0.3 単位）。
- **線路**：下地の線路網は JR九州の路線だけ（`n02/` に国土数値情報「鉄道（N02）」の RailroadSection を置けばそれから、無ければ station_database の線形＝N02 を加工したもの）。すごろくの区間は `build-geo.mjs` の `LEGS` に「路線コード・発駅・着駅」を並べ、実際の線路の上を最短でたどる。バス・航路は通過点を経度緯度で書いて曲線にする（経路のイメージ）。
- **駅**：`PLACES` に、鉄道駅は station_database の駅（緯度経度は駅データ.jp 由来）、旅のマス（黒川温泉・高千穂・屋久島）は代表地点の経度緯度を書く。
- **検証**：ビルドのたびに、鉄道の各駅について「JR 線路網からの距離」「その駅から出る区間の線路からの距離」を測り、1単位（約450m）を超えたら失敗させる（いまは最大0.16単位）。
- **出典**：`geo.js` の `source` に書き、フッターに自動で出す（元データを変えても表記がずれない）。いまは「国土数値情報『行政区域（N03）』2020年版（国土交通省）を加工（niiyz/JapanCityGeoJson が都道府県ごとに GeoJSON にしたもの）」「station_database（CC BY 4.0。線形は国土数値情報『鉄道（N02）』を加工、駅の位置は駅データ.jp 由来）」。
- **配布元について**：国土交通省の配布元（nlftp.mlit.go.jp）にこの開発環境からは接続できなかったため、N03 は上記の GeoJSON を使い、N02 は station_database の線形を使っている。配布元から取った N03 の GeoJSON（`n03/`）・N02 の RailroadSection（`n02/`）を置けば、そのまま読める（N02 は属性 N02_002・N02_004 を見る）。
- **重さ**：`geo.js` は約200KB（gzip 約72KB）。点を増やすときは `simplify` の許容値で調整する。

### アフィリエイトURLの組み立て（`app.js` の `buildUrl`）
1. `url` の `{kw}` を URL エンコードしたキーワードに置き換える
2. `params` のうち値が空でないものをクエリに足す（例：Amazon アソシエイトの `tag`）
3. `wrap` があれば、`{url}` に組み立てたURLを入れてくるむ（例：楽天アフィリエイトの `https://hb.afl.rakuten.co.jp/hgc/<ID>/?pc={url}`、バリューコマース等）

**本番前のTODO**：各サービスのアフィリエイトIDを `params`／`wrap` に設定する。楽天トラベル・じゃらんの検索URLの形式は各サービスの公式ガイドに照らして確認する（MVPでは仮のキーワード検索URL）。

### 駅を追加するとき（100駅以上への拡張）
1. `stations.json` の `stations` に1件足す（`x`/`y` は仮の値でよい）
2. 接続する駅の `connections` にも **お互いに** IDを書く
3. 新しい区間の `routeOverrides` に `type`・`name`・`minutes` を足す。離島は `type: "ferry"`
4. `tools/build-geo.mjs` の `PLACES`（駅の位置）と `LEGS`（区間がたどる路線）に足し、`node tools/build-geo.mjs <データのフォルダ>` で `x`/`y` と線形を作る（駅が線路から離れていれば失敗する）
5. `node tools/build-fallback.mjs` を実行する（検証：必須項目・memo の文字数・接続先の存在と双方向性・路線種別 → `js/stations-fallback.js` を生成）
- 駅が増えて盤面が混み合ったら、`viewBox` を広げるか、地方ごとの盤面に分ける（`meta` に盤面定義を足す）。ロジックは駅数に依存しない。

## 6. マイ旅しおり（買収駅を巡る1泊2日のモデルコース）

North Star の「購入する → **訪れる**」をつなぐ機能。買収駅が `meta.trip.minAcquired`（2駅）に届いた瞬間に、買収完了演出のボタンとトーストで一度だけ提案する（`tripPrompted`）。右側の手帳パネルと「🧳 マイ旅しおり」タブからいつでも開ける。

- **生成（`YT.Trip.generate`）**：区間の `minutes`（所要時間の目安）で全駅間の最短経路を出し、路線が変わるごとに `transferMinutes` を足す。1日目は gateway（空港・主要駅を持つ駅）を `day1Start` に出発 → 買収駅を巡る → 買収駅に泊まる。2日目は泊まった駅で朝の過ごし方（`morningMinutes`）→ 買収駅を巡る → gateway に `day2End` までに着く。時間内に収まる道順をすべて探して採点する。
  - 採点：巡れる買収駅の数 ≫ 湯けむり物件に泊まる ＞ 評価額の合計 ＞ 移動の短さ。1日目が17時より前に終わる・2日目が昼前に終わる案は減点（午後が丸ごと空く旅を出さない）。
  - 候補は最大3プラン。泊まる駅が違うものを優先し、最多より2駅以上少ない案は出さない。
  - 1泊2日に入りきらない買収駅は「入りきらなかった駅」として正直に表示する（無理な行程を作らない）。
  - 2日目が昼前に終わるときは、まだ買収していない近くの駅を「寄り道候補」として出す（次の買収につなげる）。
- **宿の比較**：このプランの宿泊地と、ほかの候補プランの宿泊地を並べ、楽天トラベル・じゃらんのボタンを置く。押すと `actions[id].stay`（ジャーニー「訪れる」）を記録する。出発日はしおりの表示用で、予約サイトのURLには渡さない（各サイトの日付パラメータ形式が未確認のため）。
- **保存**：localStorage の `itineraries` に道順（`seq`）だけを保存し、開くたびに最新データで旅程を組み立て直す。「旅の記録をリセット」では消さない。
- **そのほか**：地図でルートを見る（番号＝巡る順、泊＝宿泊地）、Xシェア、印刷（`@media print` でしおりと宿比較だけを出す）。
- **データ**：駅の `plan`（`minutes`＝滞在時間、`day`・`evening`・`morning`＝過ごし方）、`gateway`（出発・解散できる空港・駅名）、区間の `minutes`、`meta.trip`（時間割）。所要時間は乗り換え込みの目安であることを必ず画面に出す（`meta.trip.notice`）。
- 生成ロジックを変えたら `node tools/test-trip.mjs` を通す。

## 7. 称号（買収総額でランクアップ）

`meta.ranks` の順に **九州旅人（0円〜）➔ 九州開拓使（1億円〜）➔ 九州大名（3億円〜）➔ 九州鉄道王（5億5,000万円〜）**。総資産額（買収した駅の評価額の合計）で決まる。全15駅で6億7,500万円なので、鉄道王は12〜13駅前後の買収が目安。

- **表示**：ヘッダーの称号バッジ（エンブレム＋次の称号までの進み具合。押すとコレクション手帳へ）と、コレクション手帳の「称号の道」（4段階・達成/いまの称号/あと◯円・全体バー）。エンブレムはフェルトのワッペンで、色（こげ茶→藍→山吹→紅）と星の数が段階を表す（`meta.ranks` の `metal` の値は見た目の色の名前として使っている）。
- **カットイン**：買収完了の演出（`celebrate`）の中で `checkRankUp` が称号を比べ、上がっていたら買収ファンファーレの後（約2.3秒後）に重ねて出す。縫い目のある紙の帯が右から差し込み、エンブレムがぽんと押され、称号の文字が1文字ずつ降ってきて、紙吹雪が舞う。見出しは「称号がひとつ上がりました」。効果音は `Sound.rankUp()`（小太鼓のロール → 金管の和音＋シンバル → きらめき）。7秒で自動的に閉じ、クリック・Esc でも閉じる。Xシェアボタンつき。
- **一度きり**：出し終えた段階を `rankSeen` に保存し、再読み込みで同じカットインを出さない。既存データ（`rankSeen` なし）は読み込み時に現在の段階へそろえ、演出は出さない。リセットで `rankSeen` も戻る。
- しきい値や名前を変えるときは `meta.ranks` を編集する（`build-fallback.mjs` が「0円から始まる・昇順・全駅買収で最上位に届く」を検証）。称号の名前は既存ゲームの称号・役職名と重ならないこと。

## 8. ゲームロジック

- **サイコロ**：出目 n に対し、**同じ駅を二度通らない n 区間の道のり** の終点を行き先候補にする（行き止まりなら届く最長距離）。盤面全体が光らないよう、候補は **ランダムに最大3駅**（分かれ道）。候補が1駅なら自動で出発する。
- **駅を直接タップ**：最短経路（BFS）で移動する。
- **列車アニメーション**：経路の各区間の SVG パスを `getPointAtLength` でなぞる。1区間 約0.8秒＋1区間増えるごとに0.3秒。進行方向に合わせて🚂を左右反転する。到着後にチャイム → 物件カードを開く。
- **指標**：九州踏破率＝訪問駅数／全駅、王国経営度＝買収駅数／全駅、総資産額＝買収した駅の `assetValue` の合計（全15駅で67,500万円）。

## 10. 検索・共有

「Q-TRIP 九州よりみちダイス」で検索したとき、また「Q-TRIP」「九州よりみちダイス」「よりみちダイス」などの部分一致でも見つかるようにする。

- `index.html` の `<head>` 冒頭のブロックにまとめてある：`title`（アプリ名を先頭に）、`description`（アプリ名と表記ゆれを自然な文で）、`canonical`、OGP（`og:site_name`・`og:image` = `og.jpg`）、X のカード（`summary_large_image`）、アイコン。
- 構造化データ（JSON-LD）：`WebSite` の `name` と `alternateName`（Q-TRIP／QTRIP／九州よりみちダイス／よりみちダイス／キュートリップ）、`WebApplication`（無料のブラウザゲーム）。
- 画面に見える文にもアプリ名を入れる（ヘッダーの h1、「あそびかた」の一文、フッター）。検索エンジンは見えている文を重く見るので、メタ情報だけに頼らない。
- **公開URLを変えるとき**は、`<head>` のブロックの URL（canonical・og:url・og:image・JSON-LD の url と image）をまとめて書き換える。
- `og.jpg` は、まっさらな状態の盤面のスクリーンショットにロゴを重ねて作った画像。盤面やロゴを大きく変えたら作り直す。

## 11. デプロイ

**いま**：リポジトリ直下の `.github/workflows/deploy-pages.yml` が、Vite のビルド結果に `yokatabi/` を丸ごとコピーして公開している（公開URL：`https://19961029kt-prog.github.io/-/yokatabi/`）。`tools/` と `CLAUDE.md` は公開物から除く。

**移転の予定**：アプリ名の入った URL（GitHub の組織のサイト `https://<組織>.github.io/`）へ移す。手順：
1. 組織のリポジトリ `<組織>.github.io` を作る（このリポジトリの名前なら、既定のブランチに置いたファイルがそのまま公開される）
2. `bash yokatabi/tools/publish-site.sh <そのチェックアウト>` で公開するファイルだけを並べ、commit → push
3. `index.html` の `<head>` の URL を新しい URL に書き換える（検索・共有の節）。`robots.txt`・`sitemap.xml` も新しい URL で置く
4. 旧URLには転送ページを置く：`deploy-pages.yml` の yokatabi のコピーを `node yokatabi/tools/build-redirect.mjs <新しいURL> dist/yokatabi` に置き換える。転送ページは遊んだ記録を URL の # に載せて渡し、`js/store.js` が受け取る（新しい URL で先に進んでいた場合は、進んでいるほうを残す）

## 12. コーディング規約

- 依存ライブラリを増やさない（Tailwind CDN と Google Fonts のみ）。CDN の URL はバージョンを固定する。地図の元データはビルド時にだけ使い、ページは `js/geo.js` だけを読む。
- 文字列を HTML に差し込むときは必ず `esc()` を通す（データは自前でも、将来の外部データ化に備える）。
- 画面の文言は日本語。コメントも日本語で、ねらい（なぜそうするか）を書く。
- アニメーションは `prefers-reduced-motion` で弱める（`style.css` の末尾）。
- キーボードで操作できること：駅ノードは Tab で選べて Enter で動く。モーダルは Esc で閉じる。
- 1次情報（現地調査メモ）は、確かめられる事実だけを書く。営業時間・料金・所要時間など変わりやすい数字はなるべく書かず、書く場合は「約」をつける。
